# 要件定義 — ペット登録とホーム画面

対象スペック: M1（ペット登録）、M2（ホーム画面）  
対応するCONCEPT.mdセクション: 第2.1節「飼う（ホーム）」、第3.1節 M1/M2

---

## 1. 機能要件（EARS形式）

### 1.1 初回起動・ペット登録（M1）

**REQ-001**  
When ユーザーがアプリを初めて開いたとき（localStorageにペットデータが存在しないとき）、  
The system shall ペット登録画面を表示し、ホーム画面には遷移させない。

**REQ-002**  
When ペット登録画面が表示されたとき、  
The system shall プリセット3種のペット（ほしくずうさぎ / そらあるきペンギン / まめしば）を選択肢として提示する。

**REQ-003**  
While ユーザーがプリセットを選択しているとき、  
The system shall 選択中のペットのイラスト（idle状態）をプレビュー表示する。

**REQ-004**  
The system shall ユーザーが1〜12文字の範囲でペットの名前を入力できるようにする。

**REQ-005**  
When ユーザーがペット種類を選択し、名前を入力し、登録を確定したとき、  
The system shall ペットデータをlocalStorageに保存し、ホーム画面へ遷移する。

**REQ-006**  
The system shall 1ユーザー（1ブラウザ）につき1匹のペットのみ登録を許可する。2匹目の登録機能はMVPでは提供しない。

**REQ-007**  
When 名前が空、または12文字を超えているとき、  
The system shall 登録ボタンを非活性にし、入力要件をユーザーに通知する。

### 1.2 ホーム画面（M2）

**REQ-008**  
When ホーム画面が表示されたとき、  
The system shall 登録済みのペットのイラスト（idle状態）、ペットの名前、なかよし度、おもいでの数を表示する。

**REQ-009**  
When ペットが在宅状態（`state === 'home'`）のとき、  
The system shall 世話アクションボタン3種（餌をあげる・なでる・声をかける）を有効状態で表示する。

**REQ-010**  
When ユーザーが世話アクションボタンを押したとき、  
The system shall 対応するペットのリアクションイラスト（`eat` / `stroke` / `speak`）を一定時間（2秒）表示し、その後 `idle` 状態に戻す。

**REQ-011**  
When ユーザーが世話アクションを実行したとき、  
The system shall なかよし度を1ポイント加算し、変化後の値をlocalStorageに保存して画面に反映する。

**REQ-012**  
The system shall なかよし度の上限を99とし、それ以上は増加しない。

**REQ-013**  
When ペットがおでかけ中（`state === 'visiting'`）のとき、  
The system shall 世話アクションボタンを非活性にし、「おでかけ中」であることを示す表示を行う。

**REQ-014**  
When ペットが在宅状態のとき、  
The system shall 「おでかけへ」ボタンを表示する。

**REQ-015**  
When ユーザーが「おでかけへ」ボタンを押したとき、  
The system shall おでかけ選択画面へ遷移する（おでかけ機能はM3スペックで定義する）。

**REQ-016**  
The system shall ホーム画面にアルバムへのナビゲーション導線を提供する。

### 1.3 データの永続化

**REQ-017**  
The system shall ペットの状態（名前・種類・性格パラメータ・なかよし度・おでかけ状態）をlocalStorageキー `odekakepet::pet::current` にJSONとして保存する。

**REQ-018**  
When ブラウザをリロードまたは再起動したとき、  
The system shall localStorageから状態を復元し、離脱前と同じ状態でホーム画面を表示する。

**REQ-019**  
When localStorageにペットデータが存在するが、スキーマバージョンが現在と異なるとき、  
The system shall マイグレーション処理を実行してからホーム画面へ遷移する。

## 2. 非機能要件

**REQ-020**  
The system shall ビルド工程なしの静的Webアプリとして動作する（HTML / CSS / ES Modules のみ）。

**REQ-021**  
The system shall バックエンドサーバーなしで動作する（全処理がブラウザ上で完結する）。

**REQ-022**  
The system shall ホーム画面の初期表示がlocalStorageの読み込みを含めて200ms以内に完了する（低スペック端末での目安）。

**REQ-023**  
The system shall 名前入力フォームに対してXSS対策を施す（`innerHTML`への直接代入を行わない）。

**REQ-024**  
The system shall スマートフォンの縦向き表示（375px以上の画面幅）で操作できるレイアウトを提供する。

---

## 3. 制約・前提条件

- ペットの種類は3種固定（W0で素材・名称が確定してから実装する）
- 性格パラメータはM3/M4（おでかけ・イベント分岐）で使用する隠し値であり、ホーム画面ではユーザーに表示しない
- なかよし度はホーム画面の見た目（背景の変化など）に使う余地を設計に残すが、MVPでは数値表示のみで可
- 世話アクションのクールダウン（連打防止）は、リアクションイラスト表示の2秒間だけボタンを非活性にすることで実装する
