# 製品概要 — おでかけペット

## プロダクトの本質

「おでかけペット」は、2000年代のブログペット文化を現代のSNS作法で復活させるWebアプリである。ユーザーはペットを飼い、ペットはときどき友達の場所や町のスポットへ「おでかけ」し、帰宅後にその日の出来事を1枚の絵日記カードとして持ち帰る。そのカードはInstagram Storiesにそのまま貼れる縦型画像として書き出される。

復活させるのはデザインの様式ではなく**体験の核**である:
- 「自分の分身が誰かの場所にいる」という緩やかなつながり
- 送り出したら帰ってくるまで直接は見られない、非同期の不在感
- 帰宅した後の「何かあった」という小さな驚き

## 対象ユーザー

かつてブログペットを飼っていた、または「誰かのページに生き物がいた時代」を体験・知識として持つ20〜30代。現在はInstagram Storiesを日常的に使っており、「かわいい/ちょっと不思議な1枚」をシェアすることに抵抗がない層。

友達との小さなつながりを、アカウントフォローや公開ランキングではなく「コードの交換」という閉じた手触りで楽しめる人。

## コア体験ループ

```
飼う（ホーム）
  → おでかけ（送り出す）
    → 訪問先での出来事（不在中・非同期）
      → 帰宅・絵日記（持ち帰る）
        → アルバムに積む
          → また飼う
```

1周は数分で完結するが、「帰ってくるまで待つ」時間そのものが体験に含まれる。リアルタイム化はしない。この非同期性と不在感がブログペット時代の核であり、設計上の主軸である。

唯一の外向き成果物は**絵日記カード**（Stories比率の縦型PNG）であり、SNS共有はこのカード経由に一本化する。

## MVPスコープ（M1〜M8）

| # | 要素 | 最小仕様 |
|---|---|---|
| M1 | ペット登録 | プリセット3種から選択、名前付け。1ユーザー1匹 |
| M2 | ホーム画面 | ペットの部屋表示、世話アクション3種（餌・なでる・声かけ）、なかよし度表示 |
| M3 | おでかけ実行 | 訪問先の選択（おともだちコード or まちのスポット3か所）、出発→不在タイマー→帰宅の状態遷移 |
| M4 | イベント生成 | 訪問先テーマ別イベント文テンプレート＋分岐（性格・時間帯）。各スポット最低5イベント。おみやげ付与 |
| M5 | 絵日記カード生成 | Stories比率縦型画像をブラウザ側で生成し、PNGとして保存可能にする |
| M6 | おもいでアルバム | 訪問履歴・カード・おみやげの一覧表示。おみやげの部屋への配置表示 |
| M7 | 訪問される側の記録 | おともだちコードの発行、他者のペットが来た記録（足跡）の表示 |
| M8 | 提出用一式 | 動作URL、`.kiro`、write-up素材、デモ動画台本に基づく収録可能な完成度 |

**MVPの完成定義**: コアループ（飼う→おでかけ→出来事→帰宅・絵日記→アルバム）が、まちのスポット3か所とおともだちコード訪問の両方で、最初から最後まで途切れずに動作すること。

## やらないこと（スコープ外）

以下は企画レベルで除外が決定している。Kiroが実装提案を出した場合もこれに従い却下する。

- **Instagram API等による自動投稿・連携**: 共有はユーザーがカード画像を手動で保存・投稿する形のみ
- **リアルタイム要素**: ライブ訪問、同時接続、チャット、対戦
- **複雑な育成シミュレーション**: パラメータ多軸管理、進化分岐、寿命・病気等
- **課金・決済・広告**: 一切行わない
- **生成AIによる都度画像生成**: ペット・背景はプリセット素材で統一
- **ネイティブアプリ化**: Webアプリのみ、ストア申請なし
- **ユーザー間のフォローグラフ・公開プロフィール**: おともだちコードによる閉じた訪問のみ
- **複数ペット・ガチャ等のコレクション課金的手法**
- **本格的なサーバー側認証**: MVPはおでかけコード＋ブラウザ内保存で完結

## 世界観とキャラクター資産

まちの訪問先スポットは長期育成部門の既存資産と共有する:
- **星屑工房**（星屑工房のルミの工房）
- **森の標本室**（森の標本記録員テオ）
- **時計塔キッチン**（時計塔キッチンのノア）

これにより、おでかけペットのイベント文・スポット素材は各キャラクターアカウントのSNS投稿ネタとして再利用できる。再利用の際は各アカウントの開示ルールに従う。
